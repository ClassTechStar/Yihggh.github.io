第一章：先认识这台机器

你的手机，其实是你口袋里最私人的超级计算机。它比当年把人类送上月球的计算机强大无数倍，却安静地躺在你的掌心。今天，咱们就来好好认识这位「沉默的巨人」。

本章速读（5 分钟版）

这一章带你把手机拆开看：芯片、运存、存储、屏幕、电池、摄像头和传感器，一个一个认明白。它解决的不是「怎么点」，而是「为什么同一款 App 在不同手机上体验不一样」「为什么电池越用越不耐用」「为什么有些照片拍出来特别好看」。搞懂这些，你看参数表就不容易被牵着走，买手机、用手机都有底。

先抓最关键的两件事。第一件：SoC（系统级芯片）是手机的大脑，里面不只有 CPU，还有管图形的 GPU、管 AI 的 NPU、把光变成照片的 ISP 和管通信的基带。CPU 现在都是「大小核」设计——重活交给超大核猛干，刷微信这类轻活交给小核省电，全靠系统调度器自动分配。所以别只看峰值跑分：同一代芯片，散热和调度决定长时间玩游戏、导航时帧率稳不稳，看评测要优先看半小时重度负载之后的帧率曲线。运存（RAM）是办公桌，12GB 是现在的主流，16GB 适合重度用户；存储是仓库，现在主流是 UFS 3.1/4.0，比老式 eMMC 快好几倍。

第二件：摄像头的像素数不是全部。真正决定画质的是传感器大小（「大底」）、光学防抖（OIS）和镜头素质，像素只是给了个上限。变焦也分两种：光学变焦（2x、3x、5x、10x 这类固定倍数）不损失画质。数码变焦本质是裁剪放大，画质掉得厉害。电池则是手机里最「短命」的部件，用两三年就会明显老化，现在主流容量 5500-7500mAh。明白了「电池是消耗品」，你就不会把「一年后续航变差」当成手机坏了，真到那一步，换块电池往往比换整机划算。

今天就能做的最小动作：打开【设置】→【关于手机】，看看自己手机的芯片型号、运存和存储大小，跟本章的内容对上号。最大的坑是「参数陷阱」，像素越高越清晰、跑分越高越好、数码变焦当望远镜，这些想法都会让你多花冤枉钱。参数脱离场景没意义：先想清楚自己拿手机干什么，再看参数够不够用。顺带把屏幕、接口这些「门面」也认一认：HDR 让亮处更亮、暗处更暗，画面更有层次；接口认准 USB Type-C，正反都能插；手机里还藏着十几个传感器，抬手亮屏、屏幕自动旋转，靠的都是它们在默默干活。

速查表
  • 看芯片：别只看峰值跑分，看半小时重度负载后的帧率曲线更靠谱
  • 选运存：12GB 主流够用，16GB 适合重度用户，别为用不到的规格加钱
  • 看拍照：传感器大小和光学防抖比像素数重要，像素高只是上限高
  • 用变焦：光学变焦（2x/3x/5x/10x）不损画质，数码变焦是裁剪，少用
  • 电池观：它是消耗品，两三年明显老化，主流容量 5500-7500mAh
  • 认接口：USB Type-C 正反都能插、已成统一标准，Micro USB 和 Lightning 都在淘汰中
  • 挑屏幕：HDR 让亮处更亮、暗处更暗，画面层次感明显更好

本章界面路径按 iOS 18.x / HarmonyOS 5.x / Android 15 核对（2026 年 11 月）。你的机型或系统版本不同，菜单名字和位置可能对不上——以你手机上显示的为准。

一、手机硬件「五脏六腑」：深度解析

手机虽小，五脏俱全。像解剖课一样，逐个认识这些精密的组件。

1. SoC（系统级芯片）：手机的「大脑+心脏」

SoC全称System on Chip，翻译过来就是「把整个系统塞进一块芯片」。它不只是CPU（中央处理器），而是把CPU、GPU（图形处理器）、NPU（神经网络处理器）、ISP（图像信号处理器）、基带（负责通信）等等全部集成在一起。

这就像把一个城市的政府大楼、发电厂、通信中心、警察局全部建在一栋楼里，效率极高。

CPU：通用计算的核心

CPU是SoC中最核心的组件，负责处理绝大多数计算任务。手机CPU采用ARM架构，与电脑的x86架构不同，ARM架构以精简指令集（RISC）为特色，功耗更低，更适合移动设备。

CPU大小核设计：现代手机CPU普遍采用「大小核」架构（ARM的big.LITTLE技术），将核心分为不同性能等级：

  • 超大核/大核：性能最强，负责重度任务。如游戏加载、应用启动、复杂计算。频率最高（3GHz+），但功耗也最大。
  • 中核：性能与功耗平衡，处理日常中等负载任务。刷微博、看视频、多任务切换主要靠它。
  • 小核/能效核：功耗最低，处理轻量级后台任务。待机、听音乐、接收消息等，几乎不费电。

三个等级的核心协同工作：系统调度器根据任务负载自动分配——轻量任务交给小核省电，重活交给大核猛干，干完再切回小核。这就是为什么手机既能流畅打游戏，又能待机一整天。

各品牌架构特点：

  • 高通骁龙8 Elite：采用Oryon自研CPU架构（源自Nuvia收购），2个超级核（4.32GHz）+ 6个性能核（3.53GHz），全部基于台积电第二代3nm制程。彻底告别ARM公版架构，单核和多核性能均实现跨越式提升。GPU为Adreno 830，采用切片架构，图形性能提升40%，Hexagon NPU算力约45 TOPS，AI推理性能提升45%。（注：三星Galaxy定制版频率更高，超级核可达4.47GHz。）。
  • 联发科天玑9400：1个超大核（Cortex-X925，3.62GHz）+ 3个性能核（Cortex-X4，3.3GHz）+ 4个能效核（Cortex-A720，2.4GHz），全大核架构延续，台积电第二代3nm制程。GPU为Immortalis-G925（12核），峰值性能提升41%，光线追踪性能提升40%。AI处理器为第八代NPU 890，支持端侧大模型运行、端侧LoRA训练和端侧视频生成。
  • 苹果A18 Pro：2个性能核（约4.04GHz）+ 4个能效核（约2.4GHz），台积电第二代3nm制程。6核GPU支持硬件级光线追踪，16核NPU（约35 TOPS）为端侧AI和Apple Intelligence提供强大算力。苹果自研架构在单核性能和能效比上依然领先，统一内存架构为AI推理提供高带宽优势。
  • 华为麒麟9020：搭载于Mate 70系列，采用自研泰山CPU架构，NPU和ISP能力持续增强，支持5.5G和卫星通信，代表国产芯片的最新突破。

看完参数表，再给你一个防坑提醒：别只看峰值跑分。同一代芯片，峰值性能和持续性能可能差出一截，真正决定体验的是散热和调度，长时间游戏、导航、拍视频时帧率稳不稳、机身烫不烫，比跑分软件里那个一次性数字有参考价值得多。看评测时，优先看半小时重度负载后的帧率曲线。

CPU 缓存：L1 / L2 / L3，还有一颗大 SL cache

聊完核心数量，再说一个发布会上几乎不提、却实实在在影响日常体验的东西：缓存。CPU 的运算速度比内存快得多。它一拍就能算完一步，去内存里取数据却要干等上百拍。为了不让「大脑」空转，工程师在中间塞了好几层越做越大的「随身小仓库」。

  • L1 缓存：每颗核心私有，指令和数据还分开存放。容量最小（几十 KB 级），但速度也最快，一两拍就能拿到数据。L1 的存在感太强，几乎没有厂商拿它做文章。
  • L2 缓存：同样贴着核心（按核或按簇共享），容量几百 KB 到几 MB，速度比 L1 略慢。按公开拆解口径，A19 Pro 的 L2 合计有 22MB，天玑 9500 是 10.5MB。
  • L3 缓存：整个 CPU 集群共享的大仓库，几 MB 到十几 MB。核心之间传数据、互相交换结果，主要走这一层。天玑 9500 配了 16MB L3。
  • SL cache（System Level Cache，系统级缓存）：比 L3 更靠外的一层超大缓存，玩法也更新，它不只服务 CPU，GPU、NPU、ISP 都能来借。比如 A19 Pro 给到 32MB SLC（上一代 A18 Pro 是 24MB），骁龙的 SLC 起步晚（865 时代只有 3MB），近年才追上来；天玑 9500 干脆没做独立 SLC，只给 GPU 自带 4MB 私有 L2，各家路线并不一样。

为什么它重要？缓存命中率决定 CPU 要绕几次内存。同样的任务，数据正好在缓存里，几拍搞定；不在，就得等上百拍。苹果 A 系单核性能和能效长期领先，超大 L2 加大容量 SLC 是公认的功臣之一，这也是为什么同样标着「3nm」，不同芯片的日常流畅度能拉开差距。

一个实用的观察角度：缓存容量从来不进跑分软件，但同代芯片对比时，缓存结构比峰值频率更能预测「日常跟手度」。下次看拆解评测，记得留意 L2 / SLC 那两行数字。

GPU：图形渲染引擎

GPU（Graphics Processing Unit）专门负责图形和并行计算任务。它的核心数量远多于CPU（动辄数百上千个核心），但每个核心的功能相对简单，适合同时处理大量相似的计算。

图形渲染流程：

  1. 顶点处理：计算3D模型中每个顶点的位置坐标。
  2. 光栅化：将3D图形转换为2D屏幕上的像素点。
  3. 像素着色：为每个像素计算颜色、纹理、光照效果。
  4. 输出合成：将所有图层合成最终画面，送到屏幕显示。

GPU对日常使用的影响：不只是游戏！界面滑动、动画效果、视频播放、照片滤镜、AR应用都依赖GPU。GPU性能弱的手机，滑动界面可能掉帧，游戏更是直接卡顿。

各品牌GPU：高通使用自研Adreno GPU；联发科使用ARM Mali GPU；苹果使用自研GPU，性能和能效都是行业标杆。

现代手机 GPU 的七个关键词：光追、NSS、NFRU、VRS、Mesh Shading、异步计算和LPAC

前面那套「顶点 → 光栅化 → 着色」是老管线，今天的手机 GPU 在它之上叠了一整层新能力。发布会上这些词会越来越密，这里一次讲透，以后你看参数表就不用猜了。

  • 硬件光线追踪（Ray Tracing）：让光在场景里真实反弹，玻璃反光、水面倒影、角色阴影都按物理规律算出来，而不是「贴一张假的光斑图」。开销极大，所以手机上通常只在反射、阴影这些最出效果的局部开启。现状：天玑 9400 的 Immortalis-G925 光追性能比上代提升 40%，苹果从 A17 Pro 起有硬件光追单元，骁龙 Adreno 也已支持。
  • NSS 神经超采样（Neural Super Sampling）：先用低分辨率渲染画面（比如 540p），再由 AI 把它放大回 1080p——省下来的算力拿去开更多特效。这是手机版的 DLSS。Arm 在新一代 Mali GPU 里塞了一个约 150KB 的神经模型，把 540p 放大到 1080p 单帧只要约 4 毫秒，画质接近原生，2026 年起在游戏里落地（首批适配包括《燕云十六声》）。骁龙 Adreno 有自己的一套方案，思路相同。
  • NFRU 神经帧率提升（Neural Frame Rate Up-scaling，帧生成）：在两帧真实画面之间，用光流加神经推理「算」出一帧补上，30 帧就能变 60 帧。它依赖新 Mali GPU 里内置的运动矢量加速硬件。预计 2026 年下半年起在游戏里铺开。和外挂插帧芯片的区别在于：这个能力长在 GPU 里，游戏引擎可以直接配合它优化。
  • NSSD 神经超采样 + 降噪：NSS 的光追加强版，开启大规模光源（MegaLights 一类）后画面噪点多，NSSD 把降噪和超采样合成一步做完，光追画面也能保持帧率。
  • VRS 可变速率着色（Variable Rate Shading）：人眼盯着的地方全速渲染，边缘、暗部、高速运动的区域降低采样率：玩家几乎看不出差别，着色开销最多能省三成。高通、Arm、苹果的 GPU 都已支持，游戏适配后会自动生效。
  • Mesh Shading 网格着色器：把「先算顶点、再光栅化」的老管线，换成着色器直接生成并处理网格的新管线。同样的算力，能画出数量级更多的独立物体，成片的草丛、千人同屏、细到发丝的毛发。Immortalis-G925 与苹果 Metal 框架都已支持。
  • 异步计算管线与 LPAC 低优先级异步计算：GPU 画画时并不是每时每刻都满负荷，异步计算让物理模拟、AI 后处理这些计算任务塞进图形任务的空隙里并行跑。LPAC 更进一步：给后台任务标上「低优先级」，它只能捡 GPU 的空闲单元用，下载解压、后台 AI 推理都不再把前台游戏挤掉帧。这项能力苹果在 M3 系列上率先引入，A19 Pro 把它带进了手机。

给你的判断方法只有一句话：这些特性只有在游戏真正适配之后才有意义。听到发布会吹 GPU 新名词，先去查你常玩的那几款游戏有没有适配公告：适配了，是白捡的帧率；没适配，看看就好。

NPU：AI加速引擎

NPU（Neural Processing Unit）是专门为神经网络运算设计的处理器。相比CPU和GPU，NPU在处理AI任务时效率更高、功耗更低。

神经网络运算方式：NPU的核心运算是矩阵乘法和卷积运算——这正是神经网络中最基础、最频繁的计算。NPU通过硬件级优化，可以并行处理大量矩阵运算，速度比CPU快几十倍，功耗却低得多。

AI处理流程：

  1. 数据输入：摄像头图像、麦克风音频、传感器数据等。
  2. 预处理：调整数据格式和尺寸，适配神经网络输入要求。
  3. 推理计算：NPU加载训练好的模型，对输入数据进行前向计算，输出结果。
  4. 后处理：将AI输出转换为可用的结果，如人脸坐标、文字内容、场景标签。

实际应用场景：

  • 计算摄影：夜景合成、人像虚化、HDR处理、AI美颜。
  • 语音助手：语音识别、自然语言理解、语音合成。
  • 实时翻译：AI字幕、对话翻译。
  • 智能识别：文字识别（OCR）、物体识别、场景识别。
  • 端侧大模型：最新旗舰芯片已支持在手机端运行小型AI大模型（7B参数级别），实现离线AI对话、文档摘要、智能写作等功能。骁龙8 Elite的Hexagon NPU算力约45 TOPS，天玑9400的NPU 890同样支持端侧大模型（LLM推理速度提升80%），苹果A18 Pro的16核NPU提供约35 TOPS算力。
  • AI图像处理：AI消除（一键去除照片中的路人）、AI扩图（扩展图片边界）、AI风格转换、文字生成图片等。

看到「45 TOPS」这类算力数字，别急着激动TOPS不能直接换算成体验。如今「端侧 AI」已经是常规卖点：本地语音识别、图片处理、实时翻译确实跑在 NPU 上，但不少生成式任务仍要联网。买之前想清楚一件事：宣传里那个 AI 功能，你每个月真会用几次？

2026 年旗舰 NPU 的八个关键词——这一轮变化比过去几年加起来都大，逐个说清：

  • Transformer 专用硬件单元：端侧大模型清一色是 Transformer 架构，2026 年旗舰 NPU 的最大变化就是为它设计了专用计算单元——高通新一代 Hexagon 直接加了 Transformer 专用的元素加速器，把注意力计算要搬运的数据挪到计算单元旁边；天玑 9500 则用双 NPU（一颗超性能、一颗超能效）的架构主攻智能体 AI。翻译成人话：以前 NPU 是「什么 AI 都算」，现在是「专攻大模型」。
  • 多精度原生硬件支持：量化（把模型参数从高精度压到低精度）曾经靠软件模拟，现在是硬件原生直出：INT2 / INT4 / INT8 / FP8 / FP16 各档都有对应电路。精度每降一档，带宽和功耗几乎减半：同样跑一个 7B 模型，INT4 版本比 FP16 版本快好几倍。代价是精度损失，所以旗舰 NPU 让你按任务挑精度：摘要用 INT8，翻译用 INT4，都行。
  • 片上张量缓存与张量流内存架构Transformer 最吃「带宽」：注意力要反复读写很多的键值数据。新一代 NPU 在芯片里自建了大容量 SRAM 张量缓存，配合 SoC 的 L1 / L2 / SL cache 形成多级供给：数据命中片上就不必绕道内存。高通新一代 Hexagon 的共享内存直接加大了 50%，就是为了喂饱 Transformer。
  • MoE 混合专家硬件路由加速：端侧大模型正在转向 MoE（混合专家）架构：模型里有一堆「专家」，每个问题只激活其中一两个，天然省算力。2026 年旗舰 NPU 第一次在硬件层支持专家路由：门控网络选中的专家走专线，没选中的保持休眠。高通 Hexagon 首次支持 MoE，Meta 等厂商的端侧 MoE 模型与这套硬件正好软硬配合。
  • 统一异构调度引擎：CPU、GPU、NPU、ISP 各有所长，调度器决定每个任务派给谁。NPU 做 INT8 推理的能效比 GPU 高数倍，CPU 负责逻辑与调度，GPU 兜底并行计算。各家把这套跨单元调度做成了硬件引擎（命名不一，思路一致），统一内存让数据不用在单元之间反复拷贝。
  • 多模态流水线硬件：新一代模型同时「看图、听话、说人话」，NPU 里对应地出现了多模态融合的流水线硬件，摄像头画面经 ISP 处理后直送 NPU 的图像分支，语音经音频通路直送语音分支，在特征层融合后统一输出。「看到 → 理解 → 回应」不再分步排队。
  • 低功耗持续推理与后台驻留推理：抬手亮屏、语音唤醒词、锁屏画面感知，这些「永远在线」的小推理已经压到毫瓦级功耗，靠的是常驻低功耗推理通路。后台驻留则让息屏时的 AI 任务（整理相册、下载模型分片）在 NPU 上慢慢跑完，早上醒来就能用。
  • 算子扩展与开放标准（TOSA / QNN）：新模型刚发布，里面往往有 NPU 没见过的新算子，过去从模型发布到 NPU 适配要等几个月。开放标准改变了节奏：Arm 的 TOSA 统一算子描述，高通 QNN 让开发者直接把模型接到 Hexagon 上，框架更新与 NPU 驱动更新开始同频迭代。

判断方法和前面一样：这些能力最终都要落到「你真的会用的那个功能」上，本地文档摘要、实时通话翻译、照片语义搜索。发布会听完，回去打开手机试试那几个功能，比记参数有用。

ALU：三类处理器里真正「算数」的那个部件

前面把 CPU、GPU、NPU 各自干什么讲了一遍，但有个问题一直绕着没说：它们内部真正把数字算出来的，到底是什么？答案是个听起来有点老派的名字ALU（Arithmetic Logic Unit，算术逻辑单元）。它是所有处理器里最基础的「算数部件」，可三类处理器把它用出了三种完全不同的样子。更常见的一个误会是把 NPU 说成「有很多 ALU」，这一节主要就是把这件事掰清楚。

一、ALU 管什么，不管什么

先给 ALU 划个范围。它是一块组合逻辑电路，接两个操作数，按控制信号做一次运算，吐出结果。传统意义上它管四件事：

  • 整数算术：加、减，以及乘法（有的设计里乘法单独做一块）；除法常要迭代多轮或交给专门电路。
  • 位逻辑：与、或、非、异或。权限位判断、开关掩码、颜色通道拆分，靠的都是它。
  • 移位：左移右移、算术移位、循环移位。乘除 2 的幂、打包解包数据都用得上。
  • 比较：判断相等或谁大谁小，结果不写回普通寄存器，而是写进标志位（是否为零、有没有进位、溢出没溢出、结果正负）。

它不管三件事：不存数据、不决定做什么、不记住上一次算的结果。一条指令真正跑起来是这样一条链：

  • 控制单元（CU）负责取指和译码，看懂「这是一条加法」，然后发出控制信号，告诉 ALU 这次选哪一种运算。
  • 寄存器堆把两个操作数递过来（有时其中一个是指令里直接带的立即数）。寄存器是离 ALU 最近、最快的一层存储。
  • ALU只负责算这一下，结果沿写回总线送回目的寄存器，标志位送回状态寄存器。
  • 要不要跳转、下一步执行哪条，是控制单元看着标志位决定的，不是 ALU 决定的。

打个后厨的比方：控制单元是看单子点菜的人，寄存器是备料台，ALU 是灶上那口锅，只管把递来的两份料按吩咐炒一下，炒完盛回盘子，既不存菜，也不接单。

二、先把几个容易混的名字分开

现代芯片里这些单元物理上常常挨在一起、共用数据通路，所以发布会和参数表很容易把它们混着叫。但职责真的不一样：

  • FPU（浮点单元）：管浮点数。它要对齐指数、规格化尾数、处理舍入和 NaN/Inf 这类异常，电路比整数 ALU 复杂得多，是一条独立的浮点流水线。严格说它不是 ALU，虽然它内部也有加法器和乘法器。
  • 向量单元 / SIMD：一条指令同时对一组数据做同样的运算（手机上最常见的是 NEON，新一代还有 SVE 一类可伸缩向量扩展）。每个 lane（通道）里才是一个小小的 ALU 或 FPU。并行来自 lane 的数量，不是来自指令变强了。
  • 矩阵单元 / 张量核：专门为矩阵乘设计的块，一次处理一小片矩阵而不是一对数字。CPU 和 GPU 里也有这类单元，但它是另一层东西。
  • MAC 阵列：MAC 是「乘加融合」（a×b+c 一步做完，中间结果不写回）。把成千上万个 MAC 排成二维阵列、让权重和激活在里面流动，就是 NPU 的主力算力来源。它和 ALU 不是同一种东西：ALU 每做一次都要由指令告诉它「这次算什么」，MAC 阵列则是把一种固定运算铺成一张网，靠数据流喂进去。

一句话记牢

ALU 是「按指令算一次」的通用部件；FPU 专管浮点，向量单元把很多个 ALU 排成一排听同一条指令，MAC 阵列则干脆把运算固定成乘加、铺成一整片。以后听到「某芯片有几千个 ALU」，先问一句：说的是真 ALU，还是把向量 lane 和 MAC 也算进去了？

三、CPU 里的 ALU：少，但每一个都很快

  • 主要运算：整数加减、位逻辑、移位、比较，外加大量地址与索引计算。浮点交给 FPU 和向量单元，分支判断交给分支单元，读写内存交给加载/存储单元，这些都不算 ALU，但和它一起挂在核心的执行端口上。
  • 数据精度：以 64 位整数为主，也有 32 位；标量运算是常态，向量指令另说。
  • 组织方式：一个核心里通常只有几个整数 ALU（常见两到四个），配乱序发射、寄存器重命名、深流水和分支预测。整条流水线的设计目标只有一个，把单条指令的延迟压到最短，让分支密集、前后依赖强的代码也能一路跑下去。
  • 并行规模：每核个位数 ALU，整芯片也就几十个。CPU 的并行靠的是指令级并行（同时发射多条指令）和多核，而不是堆 ALU 数量。
  • 典型任务：应用逻辑、系统调度、界面事件、文件与权限判断、整数循环、数据库查询条件。这些都是「步骤多、分支多、每一步都等上一步结果」的活。

设计目标可以浓缩成四个字：低延迟、通用。宁愿把一个 ALU 做得很复杂、频率拉得很高，也不要几千个慢吞吞的。

四、GPU 里的 ALU：复制成成千上万个 lane

  • 主要运算：整数和浮点都有，主力是浮点的加、乘与乘加融合（FMA），还有插值、纹理采样和一批特殊函数；整数部分多用来算索引、地址和循环计数。
  • 数据精度：FP32 是基本盘，移动端大量用 FP16 省电省带宽，整数一般是 32 位。同一个芯片上几种精度混着跑很正常。
  • 组织方式：一堆结构相同的 lane 编成组（不同厂商叫 warp 或 wavefront），走 SIMT 路线，一条指令同时喂给组里几十个 lane，每个 lane 有自己的算术单元。遇到分支分歧时，走不同分支的 lane 暂时被屏蔽，两组先后走完，这也是为什么 GPU 怕「每个像素各走各的判断」。
  • 并行规模：成百上千个 lane，整芯片数千量级的算术单元。单 lane 慢一点根本不重要，只要同一时刻有足够多的像素或顶点在跑。
  • 典型任务：顶点变换、像素着色、光照与阴影、界面动画合成、照片滤镜，以及一部分通用计算和 AI 推理。

设计目标是高吞吐用很多并行线程把访存等待藏起来。和 CPU 放一起看特别清楚，CPU 是「少而强、求快」，GPU 是「多而简、求多」。

五、NPU 里的 ALU：主力其实不是它

这一段最容易被写错，咱们说细一点。NPU 里确实有 ALU，但只占很小一块面积，干的是辅助活；真正撑起算力的是 MAC 阵列。

  • ALU 在 NPU 里做什么：地址和步长计算、循环计数、量化与反量化的定点换算（把 INT8 按 scale 和 zero-point 还原回浮点范围）、ReLU 之类的比较与取最大值、查表、算子调度。全是标量、控制面的杂活。
  • 主力运算：卷积、全连接、注意力里那些矩阵乘，落到硬件上就是成千上万次乘加（MAC）。这不是「把 ALU 造大一点」。这是把一种运算铺成阵列，让数据在阵列里流动、权重尽量留在片上 SRAM 不来回搬——省下的搬运动量，正是 NPU 能效比高的关键。
  • 数据精度：低精度、量化是常态，INT8 在端侧推理里是主力，更激进的场景会用 INT4 或 FP8，部分层用 FP16。用精度换能效，这和 CPU/GPU 追求 FP32 准确度的取向完全不同。
  • 组织方式：MAC 阵列 + 片上权重缓存 + DMA 数据流调度，执行过程高度确定、几乎没有分支。少量标量 ALU 在旁边负责「把数据摆好、把结果收拾好」。
  • 并行规模：MAC 单元成千上万，但要注意它们都在算同一个矩阵乘的不同输出位置，不是各自独立执行不同指令：这和 GPU 里「上千个 lane 可以各自跑不同线程」是两种并行。
  • 典型任务：端侧大模型推理、夜景降噪、人像分割、语音识别、实时翻译、相册语义检索。

设计目标是每瓦吞吐（发布会上那个 TOPS/W）。它愿意牺牲通用性、牺牲精度，甚至牺牲「能跑任意程序」这件事，换来同样的电池能多跑几十倍矩阵运算。

别把 NPU 说成「一堆 ALU」

ALU 是「一条指令来，做一次通用运算」；MAC 阵列是「一份数据流进来，整片阵列同时把乘加做完」。NPU 有 ALU，但那是配角。把两者画等号，就会误以为 NPU 只是「ALU 更多的 CPU」，也就解释不了为什么它跑矩阵快、跑个带一大堆分支的普通程序反而慢。

七、把几个场景连起来走一遍

  • 整数与逻辑运算：解锁时判断某个权限位开没开、相册按日期排序、算剩余存储够不够放一段视频：全是 AND、比较、加减，CPU 里那几个 ALU 最擅长，且这类活前后依赖强，堆再多 lane 也帮不上忙。
  • 浮点运算：游戏里一帧的光照、界面滑动时的动画合成、给照片套个滤镜，几百万个像素做几乎一样的浮点运算，正好交给 GPU 的 FP32 / FP16 lane 一起算。
  • AI 推理：拍一张夜景，ISP 先把原始数据整理好，NPU 用 INT8 的 MAC 阵列跑完降噪模型，旁边的标量 ALU 负责把量化结果还原、做 ReLU 和取最大值，最后结果交回 CPU 写进文件。这里真正吃算力的是 MAC 阵列，ALU 是把边角收拾干净的人。
  • 三者接力：同一次拍照里，CPU 发号施令、ISP 预处理、NPU 推理、GPU 合成预览、CPU 收尾写盘。手机里没有谁替代谁，只有各干各的那一段。

本节小结

ALU 是「按指令算一次」的基本部件：CPU 把它做得少而快、专攻低延迟和通用；GPU 把它复制成成千上万个 lane、用同构并行换吞吐；NPU 干脆把主力换成 MAC 阵列，只留少量 ALU 做标量辅助，用低精度换能效。所以「NPU 就是 ALU 更多的处理器」这个说法是不准确的：三者差的不是数量，是为哪种计算而设计。

给你一个能带走的判断法：看到分支、逻辑、整数和「一步一步等结果」，想 CPU 的 ALU；看到像素、浮点、大量同构数据，想 GPU 的 lane；看到矩阵乘、量化、TOPS/W，想 NPU 的 MAC 阵列。发布会上的算力数字会年年翻，但这三种「算」的方式不会变：知道哪种活交给哪个部件，比记住某个数字有用得多。

ISP：影像信号处理器

ISP处理摄像头传来的原始数据，把光线信号变成好看的照片。

性能怎么看？看型号！苹果A18/A19 Pro、高通骁龙8 Elite系列、联发科天玑9400/9500、华为麒麟9020都是旗舰级别。中端看骁龙8s Gen3/Gen4、天玑8400。别只看核心数，架构和制程（纳米数）更重要。2nm制程已于2026年下半年开始在顶级旗舰上量产（能效比优于3nm），别只盯着纳米数看。2026 年在售的顶级档有骁龙8 Elite Gen 5/6 和天玑 9500/9600 系列——这份名单半年就刷新一次，买的时候认准「当年最新一代」就行。

2026 年旗舰 ISP 的九个关键词——影像 规格 表上这些新名词，一个个拆开看：

  • 编码与压缩配套硬件（APV / H.266）：拍得再好，编码跟不上也是白搭。APV（Advanced Professional Video）是 10-bit / 12-bit 色深、4:2:2 色采样的免版税专业录制编码，Android 16 起原生支持（三星推动，对标苹果 ProRes）；配套的编码硬件要能实时吞吐这样的高码率流。H.266 / VVC 则是面向分发的新一代压缩标准——同样的画质，体积几乎减半，旗舰 SoC 的编解码硬件已在逐步跟进。
  • 电影向 RAW / Log 视频管线：RAW / Log 格式把色彩与曝光的决定权交给后期，是专业视频的起点。联发科把这条管线做成了名为 CSISP 的电影向 ISP 能力——天玑 9600 Pro 支持 4K60 电影级视频直出、17EV 级动态范围；vivo 与联发科联合定义了满血 4K120 10bit Log 烧录直出。旗舰视频的竞争，已经从「能拍 4K」卷到了「直出可后期的专业素材」。
  • 高位宽原生 HDR 与传感器联动 HDR：传感器输出的原生动态范围有 14 档以上，ISP 全程高位宽处理（不中途裁成 8bit）才能保住高光与暗部细节；多摄联动 HDR 则让主摄和长焦接力曝光，变焦瞬间画面不跳变。
  • 低照度专用硬件：多光谱融合与夜视：极暗场景下，多帧合成之外，新旗舰开始引入多光谱信息融合（可见光之外的波段也参与成像），配合专用的夜景 ISP 管线做降噪与提亮。各家实现与命名不同，但方向一致：让夜景从「看得见」到「看得清」。
  • Always-On 低功耗感知 ISP：主 ISP 全开很费电，所以旗舰 SoC 里单独做了一条常驻低功耗感知通路，息屏状态下它持续盯着前置镜头：你看得起屏幕才亮屏、扫到二维码直接弹付款、检测到人脸朝向自动横竖屏切换。整套感知的功耗是毫瓦级，骁龙 8 Elite 与天玑 9400 一代均已配备。
  • 实时语义分割硬件管线（AI-ISP / 神经 ISP）：把画面逐像素标注出「这是天空、人脸、头发、食物」，传统 ISP 的全局参数随之升级为逐区域精修，天空单独提饱和度、人脸单独降噪。天玑 9400 一代起已把这套 AI-ISP 架构做进硬件。
  • 硬件光流引擎与运动补偿：光流负责估算相邻两帧之间每个像素的移动方向，电子防抖、插帧、多摄变焦接力都靠它。运动补偿硬件把抖动逐帧「搬回去」，由主 ISP 配合独立影像芯片（各家的自研影像/显示芯片）实现，部分平台的专用加速单元有自己的命名，实现方式各不相同。
  • 多摄同步配准与计算光学：变焦接力时，两颗摄像头要同时曝光并把画面逐像素配准对齐，否则切换瞬间会「跳一下」；计算光学则把镜头的光学缺陷（畸变、色散、暗角）在拍摄那一刻逐点校正，用算力补光学，是旗舰影像的新打法。
  • 异构互联架构（ISP ↔ NPU ↔ GPU 直通）：ISP 的语义图直接喂给 NPU 做像素级精修，NPU 的结果直接回 GPU 合成，数据不绕主内存，省下的带宽就是省下的电与延迟。这条「直通路」是旗舰影像 SoC 最近一年最重要的架构变化。

规格表上的这些名词，最终都指向同一件事：按下快门那一刻，「所见即所得」的程度，以及后期还剩多少空间。挑影像手机时，与其数镜头数量，不如看实拍样张的夜宵摊、演唱会和逆光人像，那才是这条管线的终点。

2. 运存（RAM）：临时工作台

运存就像你的办公桌，越大，能同时摊开的文件就越多。12GB是现在的主流，16GB适合重度用户，24GB以上则是游戏玩家和极客的选择。

运存类型也很重要：LPDDR5比LPDDR4X更快更省电，2026年旗舰标配已是LPDDR5X。苹果虽然运存不大，但系统优化好，所以看起来「够用」。

运存不够会怎样？App会被系统杀掉后台，切换时需要重新加载。这就是为什么有时候切个微信回来，游戏就没了。

另外，宣传页上「12GB+8GB」这种写法要留个心眼：加号后面那个数字，往往是内存扩展——把一部分闪存当临时内存用的软件方案，和物理运存不是一回事。存储紧张时，先清缓存和大文件，比开扩展管用。本章末尾的附章专门把这项技术讲透。

3. 存储（ROM/闪存）：长期仓库

存储就像你的书柜，装所有照片、视频、App的地方。现在主流是UFS 3.1或UFS 4.0（2025年起UFS 4.1已上旗舰），速度比老式的eMMC快好几倍。

为什么存储速度重要？它决定了App打开速度、游戏加载速度、照片保存速度。用久了之后，慢速存储会让手机越来越卡。

4. 屏幕：你的眼睛

屏幕是你和手机交互的主要窗口，好坏直接影响体验。

  • 材质：OLED色彩艳丽、对比度高、更省电（显示黑色时像素不发光），但低亮度下可能有频闪伤眼；LCD更护眼、成本低，但对比度和色彩不如OLED。
  • 分辨率：1080P是主流，2K更清晰但更耗电。苹果的「视网膜屏」概念就是：在一定距离下，人眼分辨不出像素点。
  • 刷新率：60Hz是标准，90Hz/120Hz更流畅，滑动时丝般顺滑。高刷新率会耗电，所以很多手机支持自适应刷新率（LTPO），根据内容动态调整。
  • 触控采样率：影响触控响应速度，游戏玩家要关注，越高越跟手。
  • 调光方式：DC调光比PWM调光更护眼，低亮度下不容易眼睛累。现在很多手机支持高频PWM调光，也是为了护眼。

挑屏幕，看四项就够：分辨率、刷新率、峰值亮度、调光方式。前两项大家都会看，容易漏的是后两项：峰值亮度决定大太阳底下能不能看清屏幕，调光方式决定晚上躺着刷手机累不累眼。长时间看屏幕的人，低频闪和最低亮度下的表现，比「2K」这个字眼重要得多。

屏幕HDR技术

HDR（High Dynamic Range）让屏幕同时展现更亮的亮部和更暗的暗部，画面层次感大幅提升。

  • 实现原理：普通屏幕的亮度范围有限（SDR），最亮和最暗之间的差距不够大。HDR屏幕的峰值亮度更高（通常1000尼特以上），对比度更大，色域更广，能显示更多细节。
  • 主流标准：HDR10（最基础，免费开源）、HDR10+（三星推动，动态元数据）、Dolby Vision（杜比视界，画质最佳但需授权）。手机支持哪个标准取决于屏幕硬件和系统授权。
  • 实际效果：看HDR视频时，阳光更刺眼、阴影更深邃、色彩更丰富。前提是视频本身是HDR制作的，屏幕也支持HDR显示。
影像HDR技术

拍照时的HDR和屏幕HDR是两回事。影像HDR是通过算法解决「亮处过曝、暗处死黑」的问题。

  • 算法原理：手机在按下快门时，实际拍摄了多张不同曝光的照片（欠曝保留亮部细节、过曝保留暗部细节、正常曝光保留中间调），然后将它们合成为一张高动态范围的照片。
  • 处理流程：多帧捕获、对齐补偿（防手抖）、曝光融合/色调映射、色彩校正、输出最终照片。
  • 效果优化：现在手机已经能做到「实时HDR」，取景器里看到的画面就是HDR处理后的效果，所见即所得。苹果的Smart HDR和安卓的自动HDR都非常成熟。
5. 电池与充电：能量之源

电池是手机最「短命」的部件，用个两三年就会明显老化。现在主流容量是5500-7500mAh。

  • 充电功率：安卓阵营已经卷到了100W甚至200W，十几分钟充满；苹果从iPhone 17起全系升到40W，也进入了20分钟充一半的梯队。快充伤电池吗？用原装配件问题不大，手机有温控保护。
  • 无线充电：方便但效率低、发热大。适合办公室随手充，不适合急着出门时用。
  • 反向充电：手机变成充电宝，给耳机、手表充电，应急用。
6. 摄像头：光与影的魔法

现在手机摄像头动辄三四个，各有分工：

  • 主摄：最常用的，传感器最大，画质最好。
  • 超广角：拍风景、建筑，视野更宽。
  • 长焦：拍远处，有光学变焦和数码变焦之分。
  • 微距：拍极近距离的小东西。

像素数不是全部！传感器尺寸（底大一级压死人）、光圈大小（f/1.8比f/2.4大）、防抖（OIS光学防抖很重要）都影响画质。计算摄影（AI算法）现在越来越重要，能把多张照片合成一张好照片。

CMOS 传感器：光是怎么变成数字的

刚才说「像素数不是全部」，那到底什么在决定画质？咱们先把镜头后面的那块硅片讲清楚。CMOS 图像传感器就是手机的眼睛，它的活是把照进来的光，老老实实变成一串数字，注意，只是数字，还不是你看到的照片。

一个像素里发生的事其实很朴素：光电效应。光子打进硅里的光电二极管，激发出电子；曝光这段时间里，电子一点点攒在一个叫「势阱」的小坑里，光越强攒得越多。曝光结束，电荷被转成电压，经像素里的放大器读出，再由模数转换器变成数字。于是每个像素交出一个数：这一格有多亮。

但这中间还有两道容易被忽略的机关：

  • 微透镜：盖在每个像素顶上的微型透镜，把斜着射进来的光拢到感光区里。没有它，边缘像素的光会大量打在电路上白白浪费。
  • 彩色滤光片阵列：像素本身分不清颜色，只数光子。所以每个像素上面盖一片红、绿或蓝的滤色片，最常见的排法是 Bayer 阵列（绿多、红蓝少，因为人眼对绿更敏感）。也就是说，传感器原始输出是一堆各自只有一种颜色的亮度值，得靠后面的 ISP 做去马赛克插值，才拼出全彩画面。

把这条链连起来看：光，微透镜，滤色片，光电二极管攒电荷，读出与模数转换，一串单色数字，ISP 做去马赛克、白平衡、降噪、色调映射、多帧合成，才是一张能看的照片。前面那一半是 CMOS 的本分，后面那一半是 ISP 与算法的本事。这也是为什么参数表一样的两台手机，拍出来可能完全不像，从滤色片、读出噪声到 ISP 调校，每一步都可能不一样。

顺带说一句历史：早年相机常用 CCD，电荷要一行行搬到芯片边缘统一读出，画质不错但费电、集成度低；CMOS 能在每个像素旁边就放下放大和读出电路，功耗低、能随机读取、还能把其它电路一起做进芯片，于是手机这个又小又怕热的地方，最后全成了 CMOS 的天下。

从像素到芯片：结构与技术演进

把一个像素放大了看，它不只是个感光点，里面还有几颗晶体管负责复位、放大、选择和读出（常见的叫四晶体管像素）。像素阵列下面是行选、列读出与模数转换器组成的读出电路。过去几十年手机传感器的演进，基本就是想尽办法让光多进一点、让电少绕一点、让数读得快一点。

  • 前照式（FSI）：金属布线走在感光区上方，光得先穿过线路层才能到达光电二极管。线路挡光、斜射光还容易被遮，开口率上不去。
  • 背照式（BSI）：把晶圆翻过来从背面进光，布线挪到感光区下面。挡路的东西没了，进光效率和边缘画质都明显改善，弱光表现跟着上来。今天手机传感器基本都是背照起步。
  • 堆栈式（Stacked）：再往前一步，把「感光那一层」和「逻辑电路那一层」分开做、再键合叠在一起。像素层可以专心留给光，逻辑层腾出面积放更多更快的模数转换器、缓存甚至一部分预处理电路。它换来的主要是速度——更高的连拍与视频帧率、更短的多帧合成窗口。
  • 再往细处走：列级或像素级模数转换缩短读出路径；双转换增益（DCG）按明暗切换放大方式。兼顾暗处噪声与亮处不过曝；横向溢出积分电容（LOFIC）一类做法给像素多准备一个「接溢出电荷的大容器」，把高光撑住；把一个像素拆成两个光电二极管做相位检测（QPD 一类），让对焦直接在传感器上完成。名字很多，方向就三个：多收光、别溢出、读得快、对得准。

一句话记牢

背照式解决的是「光进得来吗」，堆栈式解决的是「数读得出来吗」。前者主要帮画质，后者主要帮速度。把堆栈式当成「画质升级」是常见的误读，后面讲误区时还会再说一次。

有个坑值得单独点出来：行业里说的「1/1.3 英寸」「1 英寸」是沿用了早期摄像管的标称规格，并不等于实际对角线是 25.4 毫米。它更像一个型号名，用来横向比较同一套标称体系里的大小是可以的，别拿尺子去换算。

这几项之间还互相牵着。同一块底上，像素做小了分辨率上去，但每个像素能攒的电子变少、暗部更容易起噪；想同时要细节和弱光，就得靠像素合并与多帧算法在两种模式之间来回切。底多大、像素多大、合并怎么取舍这笔账，第十一章附「传感器尺寸与像素大小的权衡」会专门算，这里先把物理含义立住。

大底、高像素、像素合并、堆栈式：能解决什么，解决不了什么

发布会上四个词出现得最勤，但它们不是四个「升级」，而是四种不同的取舍。

  • 大尺寸传感器：解决的是「单位时间里收到的光子总数」。光多了，信噪比和单帧动态范围的上限就高，暗部更干净，也更容易拍出自然的背景虚化。解决不了的是镜头能不能把这束光好好送到整块底上——底一大，边缘像差、暗角、边角解析力、模组厚度和最近对焦距离都跟着变难。底是上限，不是结果，它得配上够好的镜头与调校才兑现。
  • 高像素：在光线充足、镜头解析力跟得上、手也稳的时候，它给的是细节与裁切空间，拍文档、拍远处建筑、二次构图确实有用。但它抬高不了暗光表现：单像素变小后，弱光主要靠合并与算法兜底；文件更大、处理更耗电、对焦与防抖的容错更小；而且在手机屏幕上或发到社交平台，多出来的细节常常根本看不到。
  • 像素合并：把相邻的几个小像素合成一个大像素输出，等于在弱光下临时换回「大像素」模式，暗部更干净、帧率与文件也更友好，所以默认拍照多半走这条路。代价是输出分辨率下来了，彩色滤光片的重排让去马赛克更绕，容易出现伪色、细节被抹平；想拿回全分辨率，得手动切高像素模式，而且最好有足够的光。它更像同一块传感器上的两套用法，不是凭空多出来的画质。
  • 堆栈式设计：主要解决「读得快」。逻辑层腾出面积放高速模数转换与缓存，连拍、高帧率视频、快速多帧合成、更轻的果冻效应都受益；片上缓存还能让多帧合成少等一会儿，逆光抓拍更不容易糊。它不直接提升单帧的收光与动态范围，成本、发热与堆叠工艺的难度却是实打实的。把它当「画质更好」看，容易买错重点。
几个流传很广的误解
  • 「像素越高越清晰」：清晰度还得看镜头解析力、对焦精度、防抖、ISP 的锐化与降噪，以及你最终在多大的屏幕上看。像素只是给了一个上限。
  • 「底大一级压死人」：这句话在暗光与动态范围上大致成立，但被用得太绝对。镜头素质、光圈、对焦、防抖、算法调校、甚至软件版本，都能让两块标称相近的底拍出不同结果。
  • 「ISO 越高越能感光」：ISO 是读出之后加的增益。光子数量由传感器面积、量子效率、光圈和快门决定，调高 ISO 只是把已有信号连同噪声一起放大，画面会变亮但不会变干净。
  • 「1 英寸就是 25.4 毫米」：前面说过，那是历史标称，不是实际对角线尺寸。
  • 「参数一样，画质就一样」：滤色片光谱、微透镜设计、读出噪声、满阱容量、ISP 与算法、镜头和固件调校全都不写在参数表里。
  • 「大底就一定虚化好」：虚化还取决于实际焦距、光圈、对焦距离和主体与背景的距离。手机更多时候是靠算法算出来的景深，跟传感器尺寸不是一回事。
  • 「动态范围高，逆光就稳了」：传感器只是给出可用的明暗跨度，最终能不能同时保住天空和人脸，还要看测光、多帧合成对不对、有没有鬼影、色调映射压得自不自然。
把参数放回场景里看

参数脱离场景就没意义，换成几个你真会碰到的画面，一下就具体了。

  • 暗光餐厅、夜里的街边：最先不够的是光子，于是传感器尺寸、像素尺寸、光圈和量子效率排在前头；此时切高像素模式往往更糟，默认的多帧降噪与像素合并才是正解。快门一长，防抖与持机稳定性又变成新的短板。
  • 窗边人像、逆光的天空：拼的是动态范围，但真正救场的是 HDR 合成。合成要连拍好几帧，读出速度不够、手一抖、人一动，就容易出现鬼影或边缘发亮的假轮廓：这也是堆栈式与快速读出在这一幕里的价值。
  • 追着跑的孩子、宠物、扫街挥手：逐行读出的卷帘快门会让快速横移的直线变斜、让挥动的手臂变形，这叫果冻效应。此时读出速度比「多几百万像素」重要得多；快门、对焦追焦和连拍能力一起决定能不能抓到。
  • 演唱会、月亮、远处舞台：长焦端的传感器通常比主摄小，光线又差，先天就吃亏。高像素裁切能补一点构图，但补不来光子；这时候别指望参数表，先看那颗长焦的底和光圈。
  • 拍文档、白天的建筑与风景：光足够、可以稳稳端住，高像素与镜头解析力才真正派得上用场，放大看细节、后期裁切都有意义。
  • 边走边录视频：读出速度决定果冻效应，防抖决定画面稳不稳，而电子防抖还要裁掉一圈视野。这一幕里「传感器强」和「视频好用」之间，隔着好几道工程取舍。

收在一句话上：CMOS 只是采集端。最终成片是「传感器 × 镜头 × 对焦与防抖 × ISP 与算法 × 显示与压缩」一起算出来的结果，参数给的是上限与倾向，不是照片本身。以后看发布会，别急着比谁的数字大——先问这个场景里最缺的是光、是明暗跨度、是速度，还是细节，再回头找对应的那一项。这么看，参数表才不会骗人。

潜望式长焦镜头

传统长焦镜头需要较长的光学路径，会让手机变得很厚。潜望式长焦通过一个90度的棱镜将光线折射，让光路在手机内部横向展开，从而在保持手机轻薄的同时实现5倍甚至10倍光学变焦。

  • 结构原理：光线从镜头进入 → 棱镜折射90度 → 沿手机宽度方向穿过镜片组 → 到达传感器。相当于把一个竖着的望远镜横着放。
  • 光学特性：光学变焦倍数高（5x-10x），画质远超数码变焦。但传感器尺寸通常比主摄小，暗光表现一般。
  • 成像优势：拍月亮、拍远处建筑、拍舞台特写，是普通手机无法企及的。
OIS光学防抖 vs EIS电子防抖

防抖是影响拍照和录像画质的关键技术，两种方式原理完全不同：

  • OIS（光学防抖）：通过物理移动镜头或传感器来抵消手抖。镜头内部有微型陀螺仪检测抖动方向和幅度，然后驱动马达反向移动镜片组。优点是不损失画质，缺点是成本高、占用空间。
  • EIS（电子防抖）：通过软件算法裁切和偏移画面来抵消抖动。手机录制稍大的画面范围，然后根据陀螺仪数据裁切出稳定的区域。优点是不需要额外硬件。缺点是会裁切画面（视野变小），暗光下可能模糊。
  • 实际选择：拍照优先看OIS，录像两者结合效果最好。现在很多旗舰手机支持「Sensor-Shift」传感器位移防抖，比传统镜头防抖效果更好。
光学变焦 vs 数码变焦
  • 光学变焦：通过物理移动镜片组改变焦距，画质不损失。手机上的光学变焦通常只有固定倍数（如2x、3x、5x、10x），不能像相机那样连续变焦。
  • 数码变焦：放大画面中心区域，本质是裁切+插值放大。放大越多，画质越差。100倍数码变焦看着很酷，但实际画质已经很糊了。
  • 混合变焦：结合光学和数码，在光学变焦倍数之间用多帧合成算法弥补画质损失。效果比纯数码好，但仍不如光学。
音频：扬声器与独显芯片

单扬声器 vs 双扬声器：

  • 单扬声器：只有底部一个发声单元，声音偏向一侧，没有立体感。中低端手机常见。
  • 双扬声器（立体声）：顶部和底部各一个扬声器，形成立体声场。看视频、听音乐时左右声道分明，沉浸感强很多。听筒兼做顶部扬声器是常见方案。
  • 音质差异：双扬声器不只是「声音更大」，关键是空间感和层次感。用单扬声器看大片，总觉得少了点什么。

游戏手机独显芯片：

部分游戏手机和性能手机配备了独立的显示处理芯片，它的作用是：

  • 插帧：将30fps的游戏画面通过算法插值到60fps或120fps，画面更流畅。这个过程在独显芯片上完成，不占用SoC的GPU资源。
  • 超分：将低分辨率画面通过AI算法提升到高分辨率，画质更清晰。
  • 降功耗：因为插帧和超分由独显芯片负责，SoC的负载降低，发热和功耗都减少，游戏更稳定。
GPS定位：单频与双频

手机定位主要依赖GPS等卫星导航系统。

  • 单频GPS：只接收L1频段信号，定位精度约3-5米。在开阔地带够用，但在高楼密集的城市峡谷中，信号反射会导致定位偏移较大。
  • 双频GPS：同时接收L1和L5两个频段信号。L5频段波长更长、抗干扰能力更强，双频联合解算可以消除大部分电离层误差，定位精度可达1-3米。在城市中导航、打车定位时优势明显。
  • 多星座支持：现代手机不仅支持GPS，还支持北斗（中国）、GLONASS（俄罗斯）、Galileo（欧洲）等多个卫星系统。同时连接的卫星越多，定位越快越准。
7. 传感器：手机的小触角

手机里藏着十几个传感器，默默工作：

  • 加速度计+陀螺仪：感知手机姿态，玩游戏转向、自动旋转屏幕。
  • 光线传感器：自动调节屏幕亮度。
  • 距离传感器：打电话时手机贴近耳朵自动熄屏。
  • 指纹传感器：现在主流是屏下光学或超声波指纹。
  • 面部识别：苹果的Face ID是3D结构光，安全级别高；安卓多为2D照片识别，安全性一般（华为Mate/Pura、荣耀Magic等旗舰已用上3D人脸）。
  • NFC：近场通信，刷公交卡、门禁卡、银行卡。
  • 气压计：测海拔高度，爬楼梯都能检测到。
  • 霍尔传感器：检测磁吸壳的开合。

二、SoC 是怎么把一件活干完的：调度、运算与数据通路

上一节把 SoC 里的部件认了个遍：CPU、GPU、NPU、ISP，还有刚讲过的 ALU。但认全零件不等于懂机器——真正让手机「跟手」的，是这些部件怎么被安排着一起干活。你点一下快门，到屏幕亮起一张夜景照片，中间要过五道手、排好几次队、等若干次信号。这一节就顺着这条线走一遍：谁负责决定做什么。谁负责决定什么时候做，数据又从哪里来、到哪里去。

先把话说在前面：下面讲的都是通用架构规律——分几层调度、有哪几种并行、地址怎么转换，各家芯片大同小异。至于一个核心几级流水、能同时发射几条指令、缓存多大、一组线程有多少个 lane，那是具体芯片实现，每一代都在变，别把书里的说法当成某颗芯片的规格表，真要查就翻厂商文档。

1. 先看全景：一次任务要过几道手

手机里几乎没有任何一件事是「应用直接指挥硬件」完成的。哪怕是给一张照片加个滤镜，也要经过这样一串角色：

  • 应用说清「我要什么」，拍一张照、跑一帧游戏、识别一句话。它只提需求，不关心谁来做。
  • 运行时与编译器把需求翻译成机器能执行的形式：一段指令、一张计算图、一串命令。顺便做优化，把能合并的合并、能提前算的提前算。
  • 驱动把这些命令写进硬件的队列，登记好依赖关系，然后敲一下「门铃」告诉硬件：有新活了。
  • 硬件调度器从队列里挑出此刻能跑的活，分给具体执行单元。它是最后一层，也是唯一真正在每个时钟周期做决定的角色。
  • 完成通知沿原路返回：硬件发中断，驱动确认，运行时唤醒等待的线程，应用拿到结果。

这条链上有个很要紧的分界：「做什么」由软件层决定，「什么时候、由哪个部件做」由硬件层决定。软件层看得到整张任务图，所以能安排顺序、合并重复、避免冲突；硬件层只看得到眼前几条指令和几个空着的执行单元，所以能在一个周期内做出软件来不及做的细粒度决定。两头各管一段，缺一头都不行。

2. 五层调度者：谁决定什么

把这五层摊开看，职责边界其实很清楚：

层决定什么不决定什么大致时间尺度
操作系统调度器哪个进程/线程上哪个核心、优先级、时间片、唤醒与睡眠；手机上还要按负载挑大核还是小核不管单条指令，也看不懂 GPU/NPU 内部的队列毫秒到微秒
运行时把 API 调用组织成命令缓冲或计算图；模型推理时做算子融合、切子图、挑后端（CPU/GPU/NPU）不生成最终机器指令，也不碰硬件寄存器每次提交前后
编译器指令选择、寄存器分配、循环展开、向量化；NPU 侧还要切块（tiling）适配片上存储、排好权重与数据搬运顺序不知道运行时会出现什么突发任务，也不控制硬件当前是否空闲安装时 / 首次运行时 / 提前离线完成
驱动把命令写进环形队列、建立同步对象、映射内存与 DMA、写门铃寄存器提交、处理完成中断不做算法优化，也不决定执行单元怎么分派提交与回收那一瞬
硬件调度器此刻哪条指令发射、哪组线程上执行单元、哪个数据块进阵列；处理结构冒险与依赖就绪看不到整张任务图，不知道应用的意图，也不做长期规划每个时钟周期

有两处边界在不同平台上会移动，值得留意。一是编译器和运行时：有的栈把图优化放在应用安装时一次做完，有的放在首次运行时，还有的干脆把一部分编译塞进驱动里，提交前才生成内核。二是操作系统和设备：CPU 线程归操作系统管，GPU/NPU 的任务队列归驱动和硬件管，操作系统通常只看到「这个进程在等一个 fence」。所以别死记「某一层一定做某件事」，记住的是这条从粗到细、从意图到周期的分工链。

手机上的操作系统调度还多一件事：能耗感知。同样一段代码放超大核上跑得快但费电，放能效核上慢一点却省得多。系统要盯着当前负载、温度和剩余电量，把前台交互这类急活给大核，把后台同步、相册整理这类不急的活慢慢挪到小核。这是手机和台式机很不一样的地方，不是「越快越好」，是「够快的前提下别把电烧光」。

3. 一次异步任务的完整旅程

用「拍一张夜景照片」当例子，把整条链走一遍。你会发现所谓异步，不是「扔到后台随便跑」，是一条有依赖图、有排队、有完成信号的流水线。

  • ① 应用提交：相机 App 发起一次拍摄请求，画面预览、降噪推理、最终编码可能一次登记好几项工作。调用立刻返回，拿到的是句柄或 future，而不是结果——这就是「异步」的起点。
  • ② 编译与图组织：运行时把降噪模型从文件里加载出来，编译器（或驱动里的编译步骤）把模型切成硬件能吃的块，安排好权重什么时候搬进片上存储，把能合并的层合成一个算子。这一步产出的是命令序列或计算图，不是结果。
  • ③ 命令排队：驱动把命令写进硬件的环形提交队列，同时把输入缓冲、输出缓冲映射好，让硬件能直接通过 DMA 读写，不必让 CPU 一字节一字节搬。写完之后敲一下门铃寄存器，硬件才知道队列里有活。
  • ④ 依赖与同步：这是最容易出错、也最容易被忽略的一步。ISP 必须先把原始帧处理好，NPU 才能开始推理；GPU 要等 NPU 出结果才能合成预览；写文件又要等编码完成。这些先后关系靠三层东西保证：信号量（队列之间「你做完我才开始」）、fence（让 CPU 能查询「硬件做到哪了」）、屏障（保证前一阶段写的数据对后一阶段真的可见，而不只是「指令发过了」）。硬件内部还有计分板一类的机制，盯着某条指令要用的寄存器准备好没有，没好就先按住不发。
  • ⑤ 硬件执行：硬件调度器从队列里取命令，把工作拆给执行单元——CPU 核上的指令、GPU 的一组组线程、NPU 阵列里的一块块矩阵，各跑各的。这一层的细节下一节展开。
  • ⑥ 完成通知：结果写回内存，硬件触发中断；驱动的中断处理先做最要紧的确认，剩下的收尾放到底半部或工作队列里；对应的 fence 被标记完成，运行时唤醒等在它上面的线程，App 的回调拿到照片，缩略图才跳出来。

这条链解释了几个日常现象：为什么点了快门要等一下才出图（在排队和推理），为什么拍照时偶尔会发热掉帧（ISP、NPU、GPU、CPU 同时抢内存带宽），以及为什么系统升级后「同样的硬件拍照变快了」（编译器和驱动把图和队列排得更好，硬件一个晶体管没换）。

一句话记牢

应用交的是「意图」。驱动交的是「命令」，硬件要的是「此刻能跑的活」。中间那些信号量、fence 和屏障，就是把「意图」安全地变成「结果」的红绿灯。异步快，是因为排队和等信号不占着 CPU 死等，不是因为可以不管顺序。

4. 硬件内部怎么把活塞满

命令到了硬件手里，接下来是一场「别让执行单元闲着」的持久战。芯片里有好几种并行，名字容易混，但它们挖的是不同层面的空档。

流水线调度是最基础的一层。一条指令要走取指、译码、发射、执行、写回几步，把这几步拆开重叠起来，就像工厂流水线：第一条还在执行，第二条已经译码，第三条正在取指。麻烦在于三种「冒险」：两个步骤抢同一个部件（结构冒险）、后一条要等前一条的结果（数据冒险）、遇到分支还不知道下一条取哪里（控制冒险）。对应的办法是前递（把刚算出来的结果直接旁路给下一条，不等写回）、分支预测和必要时停顿或冲刷。预测错了要推倒重来，代价不小，这也是为什么 CPU 特别怕分支密集的代码。

指令级并行（ILP）与多发射：一个周期只发一条指令太浪费，于是宽发射的核心一次取多条、译多条、发多条。能同时发几条就是发射宽度，是具体芯片实现，各代不同。但发得出去不等于能一起跑——得看这几条指令彼此有没有依赖、有没有空着的功能单元、寄存器堆能不能同时供上那么多操作数。

乱序执行是挖 ILP 的主力手段。编译器给出的指令顺序是「按程序逻辑排的」，硬件可以在不改变最终结果的前提下，把后面那条不依赖前面结果的指令提前做。为了让这件事安全，硬件做了两件配套：寄存器重命名，把指令里写的那些架构寄存器映射到更多物理寄存器上，消掉本来只是「名字撞车」造成的假依赖；重排序缓冲，让指令可以乱序执行、但必须按序退休，这样一旦发生异常，机器状态仍然停在正确的那条指令上。所以准确说法是「乱序执行、按序提交」，不是「随便乱跑」。

线程或任务并行换了一个层面：不再盯着单条指令，而是让多个线程、多个任务同时在跑。CPU 靠多核和同步多线程；GPU 把大量线程编成组，一组暂时等内存时立刻切到另一组，切换开销极小（上下文本来就常驻在寄存器堆里），用「线程多」来把访存延迟藏掉；手机后台同步、音频解码、界面渲染各占一条线，也是这一层。

数据并行再换一层：同一条指令同时对一批数据做同样的运算。CPU 的向量扩展、GPU 的一组 lane、NPU 阵列里同时算的许多输出点，都属于这一类。它和线程并行的区别在于：线程并行是「很多条不同的执行流」，数据并行是「一条执行流带着一大片数据」。

把这三者和上一节的 ALU 连起来看就通了：流水线是让同一个部件别空转，多发射与乱序是让一个核心里的几个部件同时忙，线程与数据并行是让整片芯片同时忙。层级越往上，需要的调度越「粗」、越依赖软件事先把活切好。

5. CPU / GPU / NPU 的调度器：粒度、目标与限制

三类处理器都有「调度器」，但调的东西完全不是一回事。用一张表收住：

一句话概括差别：CPU 的调度器在「猜」，GPU 的在「换」，NPU 的在「照着做」。CPU 面对的是走向事先猜不准的程序，得靠分支预测和乱序去赌下一步；GPU 面对的是大量同构线程，一组卡住就换另一组，不需要猜；NPU 的活早在编译器里就切好排好了，硬件按图流水即可，省下的动态决策电路全变成了能效。

这也解释了三者为什么不能互相替代。让 NPU 去跑一个满是分支的应用逻辑，它连「下一步该走哪」都没法灵活决定；让 CPU 去跑矩阵乘。它那些精密的乱序电路全用不上，还每个数据都要过一遍指令。分工不是谁比谁强，是各自把调度成本花在了最值的地方。

6. 算数的地基：加法器、乘法器与算术运算单元

上一节讲了 ALU 是「按指令算一次」的部件，这一节往里再看一层：那个「算一次」，物理上到底是什么在算。

  • 加法器是地基中的地基。一个全加器把三个一位输入（两个加数位加一个进位）变成「本位和」与「进位输出」；把它们串起来就能算多位加法，但最朴素的行波进位要等进位一级一级传过去，位数越多越慢，于是有了超前进位、进位选择这类提前算进位的做法。加法器不只是做加法：减法用补码变成加法，比较是做一次减法再看标志位，地址计算、循环计数、跳转到哪一行，底层都是它。
  • 乘法器贵得多。本质上是一堆「部分积」移位后相加，工程上用 Booth 编码减少部分积数量、用压缩树把多层加法并成少数几层，再做一次最终加法。它占的面积和耗的时间都远大于加法器，所以早期处理器常常把整数乘法单独做一块，甚至用多周期迭代完成。上一节说的 FPU 里也有乘法器，只不过它算的是浮点尾数，前后还要处理指数与规格化。
  • 算术运算单元是把这些零件装到一个框里：加法器、乘法器、逻辑门阵列、桶形移位器、前导零计数，再加上一组多路选择器：控制信号说「这次做加法」，就把加法器的结果选出去；说「这次做异或」，就选逻辑门的结果。这个带选择器的组合体，就是整数执行单元／ALU 的实体形态。它自己不会挑活，挑活的是控制单元发来的那几位控制信号。

把这个和 NPU 的 MAC 阵列接上，会看到一个很实在的差别：MAC 就是把乘法器和加法器焊在一起，中间结果直接进累加器，不写回寄存器、下一轮也不用再读回来。一次乘加省掉一写一读，成千上万次乘加省下的搬运动量，正是 NPU 能效比 CPU、GPU 高的一大微观原因。所以 MAC 不是「更快的 ALU」，是「把某一条固定路径做到极致」。

7. 指令集、微架构与寄存器：三层契约

这三个词经常一起出现，但说的不是一回事，分清了能少踩很多坑。

  • 指令集（ISA）是软件和硬件之间签的合同：有哪些指令、指令长什么样、程序员能看到哪些寄存器、内存怎么寻址、异常怎么处理。编译器只按这份合同生成机器码，不必关心芯片内部长什么样。手机上常见的合同是 Arm 的 AArch64 一类。
  • 微架构是这份合同的一种具体实现：流水线分几级、一个周期能发几条、重排序缓冲多大、分支预测器怎么设计、缓存几层各多大、有几个整数 ALU。同一份 ISA 可以做出完全不同的微架构，这正是手机大小核的依据：大核和小核跑的是同一套指令，但内部一个宽而深、一个窄而省，同一段机器码放上去跑，速度和耗电都不同。
  • 寄存器要分两层看。ISA 里规定的是架构寄存器，数量固定，编译器眼里的世界就这么大；微架构里实际用的是物理寄存器，通常多得多，专门用来给寄存器重命名提供「备用名字」，好把假依赖拆开。寄存器堆能同时读写几个端口，直接卡住了多发射的上限，发得出去，也得供得上操作数。

拿做菜再比一次：ISA 是菜谱上写的「切块、下锅、调味」这些标准动作；微架构是这家厨房有几个灶、几个厨师、备料台多大；寄存器就是灶台边那几个备料格，格子的数量和同时能伸进去几只手，决定了能并行备几道料。三者对上了，才知道为什么「同一份程序在不同手机上跑得不一样快」，合同没变，厨房变了。

8. 数据从哪来：TLB、缓存、内存控制器、带宽与总线

前面几节都在讲「算」，可现实里芯片大部分时间是在等数据。一次访问要从应用看到的虚拟地址，一路走到内存颗粒，沿途每一站都可能成为瓶颈。

  • TLB是地址转换的缓存。应用用的是虚拟地址，硬件要的是物理地址，这层映射记在页表里；每次都去查页表太慢，于是把最近用过的映射存在 TLB 里。命中就直接拿到物理页，未命中要做一次页表遍历，代价可能是几十上百个周期。用大页、让数据访问更集中，都是为了少踩这种未命中。
  • 缓存层次是延迟与容量的折中：一级最小最快、通常每个核心私有；二级大一点、可能一簇核心共用；三级或系统级缓存全芯片共享，ISP、GPU、NPU 也能借它中转。越靠上越贵，放不下太多；越靠下越慢，但能装得多。命中率上不去，ALU 再快也只能空转。多部件共享数据时还要维护缓存一致性，保证 CPU 写进去的值，GPU 或 NPU 随后读到的是新的，不是缓存里的旧副本，这正是第 3 节那些屏障要解决的问题之一。
  • 内存控制器是最后一道关卡：把读写请求排到 DRAM 的各个 bank/rank 上，合并相邻访问、安排刷新、决定谁先谁后。手机上它还得讲服务质量——屏幕扫描和预览帧不能等，后台下载可以让一让。同样一块内存，控制器调度得好不好，实际体验差得出来。
  • 带宽与延迟是两件事。带宽是每秒能搬多少数据，延迟是发起一次访问要等多久。大数据块连续读写吃带宽，零散的小访问吃延迟。CPU 靠缓存把延迟压下去，GPU 和 NPU 靠很多并行把等待「藏」在别的线程或数据块后面，这也是为什么它们不怕延迟高，却特别怕带宽不够。
  • 频率决定一秒有多少个时钟周期，同一段微架构下频率越高性能越高，但动态功耗大致随频率和电压平方一起涨，手机的散热和电池很快就会把它按住，于是系统不断在升降频（DVFS）。发布会上那个峰值频率，往往只能维持很短一会儿；真正影响长时间游戏或录像的，是散热压住之后的持续频率。
  • 总线互联是把这些部件连起来的片上网络：CPU、GPU、NPU、ISP、显示、内存控制器都挂在上面，共享有限的通路。多路同时访问就会争用，需要仲裁和优先级。上一节讲 NPU 时提到「ISP 处理结果直送 NPU 的图像分支」，这类专用直通路径的意义就在这儿，绕开公共总线，少一次排队、少一次往返内存。

把这一节塞回拍照那个例子：ISP 写帧、NPU 读权重和特征、GPU 合成预览、CPU 编码写文件，四路同时抢内存带宽和总线。这时候瓶颈往往不在「谁的算力不够」，而在数据搬不动。所以看手机性能，只盯着算力数字很容易看偏：得连着存储与互连一起看。

9. VPU、DSP 与 ECC：三位专职配角

SoC 里还有几个不常上发布会、却天天在干活的部件。它们不是同一类东西，别混着记。

  • VPU（视频处理单元）是专做视频编解码的固定功能硬件：运动估计、变换、熵编码、环路滤波这些步骤直接做成电路。录 4K 视频、视频通话、投屏、边下边播，靠的都是它。用 GPU 的通用算力也能算，但固定功能电路干同一件活省电得多，手机能连续录很久而不烫，很大程度是 VPU 的功劳。
  • DSP（数字信号处理器）是颗小而省、乘加很快、时序确定的处理器，专门伺候连续不断的信号流：通话降噪与回声消除、语音唤醒词常驻监听、陀螺仪与马达数据滤波、部分基带处理。它的价值在于不用把大 CPU 叫醒——抬手亮屏、「嘿 Siri」这类永远在线的小活，交给 DSP 常驻跑，功耗可以压得极低。
  • ECC（纠错码）不是加速器，是可靠性部件。内存、缓存、片上存储里的位可能因干扰或低电压翻转，ECC 加一点冗余位来发现并纠正单比特错、发现双比特错。手机在内存和关键片上存储里用它来扛低电压运行、提升稳定性；车规和服务器场景要求更严。把它和 VPU、DSP 并列，容易误以为它也在「算」，其实它只保证算出来的数没被悄悄改掉。
10. IPC：怎么算，以及为什么不能只看它和频率

IPC 是 Instructions Per Cycle，平均每个时钟周期完成多少条指令。它不是一个出厂标好的参数。它是跑某段程序时测出来的比值：用处理器里的硬件性能计数器读出「退休的指令数」和「实际活跃周期数」，两者相除就得到 IPC。注意分子是退休的指令：乱序执行里那些预测错、被冲刷掉的指令不算数。

一段程序花的时间，粗略可以写成：耗时 ≈ 指令总数 ÷（IPC × 频率）。这行式子把三件事都摆出来了，也顺便说明只盯其中一个为什么容易看偏。

  • 频率相同，IPC 可以差好几倍：微架构的发射宽度、乱序窗口、缓存和分支预测都在影响每周期能真正做完多少条。所以「3GHz 一定比 2.5GHz 快」这种说法，跨代、跨大小核就不成立。
  • IPC 高，也不代表更快：编译器换一版、指令选得不同，指令总数可能变少，IPC 反而「变低」但程序更短；反过来，一段被访存停顿拖住的代码，周期数变大，IPC 会掉，可它未必是芯片不行，可能是数据没喂上。
  • 指令数本身就不对等：一条向量指令能同时处理一批数据，一条 NPU 层面的「命令」背后可能是整个矩阵块。这类活 IPC 可能低得可怜，实际吞吐却高得离谱。拿标量 IPC 去比较 GPU 或 NPU，基本没有意义。
  • 并行度不在公式里：IPC 描述的是单条执行流每个周期做多少。GPU 靠成百上千组线程、NPU 靠阵列里同时算的许多输出点把吞吐堆上去，它们的强项根本不在这一列指标上。
  • 手机还要看持续表现和能耗：峰值频率会被散热按住，长时间负载下真正稳定的是持续频率；同样的活，用专用部件（VPU、NPU、DSP）做完花的能量，可能比让通用核心硬扛少一个量级。

所以更靠谱的看法是：先看单位时间完成了多少真实工作（每秒出几帧、一次推理多少毫秒、导出一段视频多久），再看单位能耗完成多少（同样的活掉多少电、烫不烫），最后才用 IPC 和频率去解释「为什么会这样」。它们是诊断工具，不是成绩单。

11. 把一部手机的一天串起来
  • 抬手亮屏：DSP 常驻听着传感器数据，判断出抬手动作，才把应用处理器叫醒；CPU 的能效核先接住，操作系统调度器决定要不要动用大核。
  • 刷信息流：CPU 处理列表逻辑与网络回调，GPU 把一屏卡片和动画画出来，VPU 顺手解着信息流里的视频，内存控制器在几路请求之间排优先级。
  • 拍一张夜景：ISP 整理原始帧、编译器事先切好的计算图进 NPU，MAC 阵列跑降噪，标量 ALU 做量化与取最大值、GPU 合成预览、VPU 如果要录像同时开工、CPU 收尾写文件。整条链靠信号量和 fence 串起来，四路一起抢带宽。
  • 玩一局游戏：CPU 跑逻辑与物理、GPU 成批算像素、DSP 处理语音、总线和内存带宽被同时占用；跑上十几分钟，散热开始压频率，这时候决定帧率的往往不是峰值算力，而是持续频率与带宽。

本章小结

把这一节收成三句话。第一，调度是分层的：操作系统管线程、运行时与编译器管图和指令、驱动管队列与同步、硬件调度器管每个周期发射什么，越往下越细、越往上越看得全。第二，并行是分层的：流水线让一个部件不空转，多发射与乱序让一个核心里的部件同时忙，线程与数据并行让整片芯片都忙起来；CPU 在猜、GPU 在换、NPU 照着编译好的图做。第三，算得快慢取决于数据喂不喂得上：TLB、缓存、内存控制器、带宽、频率和总线互联共同决定了执行单元有没有活干，也决定了峰值数字能不能持续。

给你一个能带走的判断法：看到「卡」，先问是算不过来、等数据，还是在排队等依赖；看到「快」，先问是硬件更强，还是编译器和驱动把活排得更好。频率和 IPC 只是线索，真正该看的是单位时间做完了多少事、为这些事付了多少电。至于具体几级流水、几发射、缓存多大——那是每颗芯片自己的实现，别当成通用规律记。

三、操作系统：安卓 VS iOS VS 鸿蒙

硬件是身体，操作系统是灵魂。三大系统各有特色：

  • 安卓：像开源社区，手机厂商可以深度定制。选择多。你可以换主题、装第三方应用商店、折腾各种玩法。但也因为开放，碎片化严重，不同品牌体验差异大。
  • iOS：像精心打理的花园，苹果软硬件一手抓，体验统一流畅。应用质量高，隐私保护好，但自由度低，很多事得按苹果的规矩来。
  • 鸿蒙：华为的新物种，主打分布式能力，可以让不同设备无缝协同。后面我们会专门讲。

三者生态都极其丰富，选你喜欢的生活方式就好。没有绝对的好坏，只有适不适合。

四、手机接口全解析

手机接口是连接外部世界的桥梁，不同接口差异很大：

Micro USB
  • 物理特性：扁平梯形接口，分正反面（插反了插不进去）。已经在手机上基本淘汰，但部分低端设备和老设备仍在使用。
  • 传输限制：仅支持USB 2.0标准，最高传输速率480Mbps，充电功率通常不超过10W。
  • 缺点：正反面不通用、插拔寿命短、传输速度慢、充电功率低。
Lightning（苹果闪电接口，已淘汰）
  • 物理特性：苹果自研的8针接口，正反都可以插。iPhone 14及更早机型使用，现已全面淘汰。
  • 传输限制：Lightning接口物理上仅支持USB 2.0标准，最高传输速率480Mbps。即使使用USB-C转Lightning线，传输速度也受限于Lightning接口本身。
  • 淘汰原因：欧盟通过法规要求2024年起所有手机统一使用USB-C接口，苹果从iPhone 15系列开始全面改用Type-C。Lightning接口正式退出历史舞台。
  • 注意：苹果MFi认证的数据线内含认证芯片，非认证线可能无法正常充电或传输数据。如果你仍在使用旧款iPhone，建议备好Lightning数据线。
USB Type-C
  • 物理特性：24针脚的椭圆形接口，正反都可以插。已成为手机和多数电子设备的标准接口。欧盟已立法要求2024年起所有手机、平板、耳机等便携设备统一使用USB-C接口，全球其他地区也在跟进。
  • 传输协议：Type-C只是接口形态，实际传输能力取决于内部协议。支持USB 2.0（480Mbps）、USB 3.0/3.1/3.2（5-20Gbps）甚至USB4（40Gbps）。
  • 重要区分：并非所有Type-C接口都支持USB 3.0！很多手机虽然用Type-C接口，但内部只连接了USB 2.0的引脚，传输速度和老接口一样慢。iPhone 16/17标准版仅支持USB 2.0速度，Pro版才支持USB 3.0（需使用USB-C to USB-C线）。
  • 充电能力：支持USB PD等快充协议，最高可支持240W充电。
  • 视频输出：支持DisplayPort Alt Mode，可以通过转接线输出视频到显示器。
3.5mm音频接口
  • 物理特性：圆形3段或4段插孔，3段传输左右声道音频，4段多一个麦克风通道。
  • 特点：模拟信号传输，即插即用，不需要驱动或转换。音质稳定，延迟为零。
  • 现状：大部分旗舰手机已取消3.5mm接口，需要Type-C转接线或使用蓝牙耳机。部分中端机和游戏手机仍保留。

最后补一句：接口只是硬件的一半，协议才是另一半。买手机、配配件之前核对四件事，充电协议是否通用（第三方充电器能不能跑满标称功率）、是否支持 eSIM、蓝牙版本与音频编码、有没有 NFC。这几项直接决定你的充电器、耳机和出行体验，比接口形状本身重要得多。

六、基带与天线：手机通信的幕后功臣

手机能打电话、上网，靠的是基带芯片和天线这对搭档。

基带芯片：

基带是手机中负责无线通信的处理器，它将数字信号调制成无线电波发出去，也将接收到的无线电波解调成数字信号。基带性能直接影响通话质量、上网速度和信号稳定性。高通是最大的手机基带供应商，联发科、三星也有自研基带。苹果从iPhone 16e开始搭载自研的C1基带芯片，标志着苹果正式进入自研基带时代，C1基带采用4nm制程，功耗表现优异；iPhone 16/16 Plus用骁龙X71、16 Pro/16 Pro Max用骁龙X75 5G，预计后续机型将逐步过渡到自研基带。更早的iPhone XS/11系列使用Intel基带时信号表现不佳，是不少用户的痛点。

天线设计：

手机天线藏在机身内部，通常围绕边框布置。天线设计直接影响信号接收性能：

  • MIMO技术：多入多出，使用多个天线同时收发数据，提升速度和稳定性。4×4 MIMO比2×2 MIMO速度更快。
  • 天线数量：旗舰机通常有十几个天线（蜂窝、Wi-Fi、蓝牙、NFC、GPS各需要独立天线）。
  • 金属机身的影响：金属会屏蔽信号，所以金属机身手机需要设计天线带（边框上的塑料条）。玻璃和塑料机身对信号影响较小。
网络技术演进：
  • 4G LTE：理论峰值速率下行可达1Gbps以上（Cat.16/18），实际体验通常50-150Mbps。覆盖最广，够用。
  • 5G NR：理论峰值速率下行10Gbps+。Sub-6GHz频段覆盖较好，mmWave毫米波速度极快但覆盖极小。
  • 5G-A（5G Advanced）：5G的增强版，也叫5.5G。下行速率可达10Gbps，上行1Gbps，连接数密度和定位精度大幅提升。2024年起中国移动、电信、联通开始在重点城市部署5G-A网络，华为Mate 70/80系列、小米15/17系列等旗舰手机已支持5G-A。5G-A还带来了「通感一体」能力，基站可以同时通信和感知环境，为低空经济（无人机配送）和车联网提供基础设施。
网络频段分类：

手机支持的网络频段决定了它能在哪些国家、哪些运营商的网络上使用：

  • FDD-LTE Band（B系列）：如B1、B3、B5等，4G频段。不同国家使用不同频段，中国FDD主要用B1/B3/B5/B8。
  • TDD-LTE Band：4G的另一制式，中国大量使用B38/B39/B40/B41。
  • 5G NR Band（N系列）：如n1、n3、n28、n41、n78、n79等。n78（3.5GHz）是中国5G主力频段，n41（2.5GHz）移动使用较多。
  • 购买建议：如果需要出国使用，购买前确认手机是否支持目标国家的频段。国行手机通常对中国频段支持最全，但可能缺少部分海外频段。
蜂窝基带（BP）到底管什么：

前面说「基带把数字信号调制成无线电波」，这句为了方便理解做了简化。真拆开看，BP（Baseband Processor，基带处理器）只管数字这一半：它产出的是一串比特或基带样值，并不直接把电波送出去。把比特变成电磁波，是后面射频前端的活。

BP 的活分两类。一类是把数据搬过无线信道：发送时做信道编码、加校验、调制、成帧，让数据扛得住干扰和衰落；接收时反过来做同步、信道估计、均衡、解调、解码，出错的还要靠重传合并补回来。另一类是守着空口的规矩：小区搜索与注册、切换、功率控制、重传、加密与鉴权，全都对时间极敏感——晚几毫秒，基站那边这一帧就过去了。

所以它内部大致是这么一套零件：

  • 实时处理器子系统：一颗或多颗 DSP 加控制核心，跑自己的实时操作系统。它不跑安卓、也不跑你的 App，只伺候空口那些按时辰办事的任务。
  • 调制解调硬件：OFDM 的调制与解调、快速傅里叶变换、信道估计与均衡、多路天线的信号分离。这些运算规律固定、量大，做成专用电路比让通用 CPU 算省得多。
  • 信道编解码与重传：不同代际用的编码方案不一样，但思路一致，加冗余、检错、错了请求重传并和旧数据合并。信号越差，这部分越忙。
  • 协议栈加速与定时：把数据切段、排序、加解密、压包头、守住收发时刻，都要按协议精确到时隙。
  • 三类接口：往上是与应用处理器（AP）的高速链路（片内总线或高速串行接口），往旁边是与射频前端的数字接口，还有一路连到 USIM 卡做鉴权。
  • 功耗状态管理：没有数据时让接收机按节奏短暂醒来听一下寻呼，其余时间睡过去：手机待机能撑一整天，很靠这套机制。

和 AP 的分工值得单独说一句：应用处理器跑操作系统、界面和网络上层协议，基带跑确定性最强的空口部分，两边各跑各的系统。AP 睡着的时候 BP 还醒着，继续守着寻呼、注册和小区切换：这就是为什么关屏一整夜，早上仍能立刻收到消息。参数表上写的「基带型号」，指的就是这颗；它既不是 SoC 里的 CPU/GPU/NPU，也不是射频前端。

从数字到电波：基带、射频前端与天线怎么接力：

把一次「发出去」和一次「收进来」连起来看，整条链就清楚了。

  • 发送：BP 编好码、调好制，数模转换或数字射频接口，收发机把信号搬到射频频率，功率放大器（PA）把功率提到能传出去，滤波器与双工器挑干净该发的频段，天线调谐匹配，天线辐射出去。
  • 接收：天线感应到微弱信号，滤波，低噪声放大器（LNA）先放大而不引入太多噪声，下变频搬回低频，模数转换，回到 BP 做同步、均衡与解调。
  • 闭环控制：BP 不只递数据，还一刻不停地调 PA 的发射功率、接收增益、滤波器与天线调谐。信号好就把功率收小省电，信号差就往上抬——这几条控制线是整条链路的「神经」。

为什么非要分成数字和射频两段？两个很实在的理由：空口的时序细到毫秒以下，交给通用操作系统调度根本来不及，得有独立的实时处理器；而射频是模拟电路。工艺、供电和抗干扰的要求跟数字逻辑完全不同，往往单独做、也常常单独封装。基带管「算什么」，射频前端管「怎么把这段信号送上天」，中间靠那组控制信号把它们缝成一条闭环。

手机上的几个日常现象，顺着这条链就讲得通：在电梯或地下车库，PA 得把功率拉满，于是发热、掉电都变快；手握姿势挡住某根天线。调谐与多天线选路要重新调整；金属边框必须留出天线带，否则等于给信号盖了层盖子。所以「信号差更费电」不是错觉，是发射链路在替你使劲。

集成基带与外挂基带：

基带和 AP 是做在同一颗芯片里，还是各做各的，是整机设计里一个很实际的取舍。两种方案长期并存，谈不上谁更先进。

对比项集成基带（与 AP 同一颗 SoC / 同封装）外挂基带（独立芯片）
结构共用片内互连、内存与电源管理，AP 与 BP 之间走片内通路两颗芯片通过高速接口相连，各自带自己的内存与供电
功耗与面积省掉片间往返，功耗与占板面积都更省多一次数据搬运，多一颗芯片的位置、供电与散热

一句话收住：集成赢在省，外挂赢在活。省的是电、面积和成本，活的是组合、版本与迭代。看到某款机器用哪种方案，别急着下「先进/落后」的结论，先看它要覆盖哪些市场、机身留了多少空间、这一代是不是正处在切换期。

SA 与 NSA：两种 5G 组网：

先厘清一件事：SA 和 NSA 说的是运营商那张网怎么搭，不是手机的频段，也不是「支不支持 5G」的开关。手机要能用，得在基带的协议栈里支持对应模式；但决定你连到哪种网的，是基站和核心网。

  • NSA（非独立组网）：5G 基站负责接入，但控制面仍锚在4G 核心网上，还要 4G 基站当锚点。手机同时连着 4G 和 5G（双连接），注册、切换这类信令走 4G，用户数据可以走 5G 那条快路。好处是能借现成的 4G 网快速铺开、早期覆盖好；代价是高级能力受 4G 核心网限制，两路射频同时工作也更容易费电。
  • SA（独立组网）：5G 基站配 5G 核心网控制面和用户面都走 5G，不再依赖 4G。低时延、网络切片、边缘计算、很多连接这些「完整 5G 能力」要靠它才发挥得出来；代价是核心网得新建，覆盖要一点点铺，早期不如 4G 兜底稳。

两个常见混淆值得点破：SA/NSA 不等于 Sub-6 与毫米波——后者说的是频段，前者说的是网络架构，两件事可以任意组合；也不等于「手机支不支持 5G」，同一部手机两种模式都能支持，实际连上哪种取决于当地网络。上一小节讲的 4G、5G、5G-A 是代际，这一小节讲的是每一代里网络怎么搭，别叠在一起记。

Wi-Fi 与蓝牙基带：

同一部手机里还跑着另外两套「基带」。它们和蜂窝基带是完全不同的系统：用的是非授权频谱，不需要 SIM 卡，也不连运营商核心网，覆盖从几米到几十米，发射功率低得多，而且更多由应用处理器上的操作系统直接管。

  • Wi-Fi：物理层同样用 OFDM，和蜂窝技术有亲缘，但接入方式根本不同：没有基站统一排时隙，大家靠竞争信道（先听有没有人在发，空了再发，撞了就退避重来）。多天线、波束成形、信道选择与漫游、加密都在协议栈里。它追求的是短距离内的高吞吐，代价是设备一多、距离一远，竞争和干扰就会把速度拉下来。
  • 蓝牙：靠跳频在拥挤的 2.4GHz 里躲干扰，设备组成一个小小的微微网，双方约好「连接事件」，其余时间睡过去。经典蓝牙偏向持续音频，BLE（低功耗蓝牙）把「睡很久、醒很短」做到极致，一颗纽扣电池能撑几年，耳机、手表、手柄、防丢标签、靠近解锁，都是它。
  • 工程上的现实：Wi-Fi、蓝牙（有时还有 FM 与定位接收）常合在一颗连接芯片里，与蜂窝基带并行工作、各跑各的协议栈。但 2.4GHz 与部分蜂窝频段挨得近，同时收发会互相干扰，需要共存仲裁在时间和频率上错开——开热点时蓝牙耳机偶有卡顿，多半就是这套协调在打架。

把这一节收成一句判断法：以后看到「信号不好」，别只盯着那几格，先问是哪张网（SA 还是 NSA、覆盖够不够），再问哪个频段，最后才看基带与射频前端这一条链有没有被握姿、金属边框或弱场拖住。频段、组网、基带、射频前端是四件不同的事，分开想，问题就好定位了。

七、你的手机，到底在扮演多少角色？

它早已不只是电话：

  1. 通讯工具：电话、短信、微信、邮件……
